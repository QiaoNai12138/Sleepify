# Sleepify

## ⚠️ 平台限制（必读）

### 严禁使用：AMD Ryzen 5000 / 6000 / 7000 移动端标压（H / HS / HX）

**不是怕它热，是怕它闲。**

这几代移动端标压锐龙存在**硅片退化（"缩肛"）**问题。退化后的芯片在**低使用率、低电压**工况下稳定性极差，**内存控制器首当其冲，甚至直接崩溃**。

关键在于：**高负载高电压反而是安全的，空载低压才是失效区**。而本工具的核心设计恰好是：

| 本工具的动作 | 对退化芯片的意义 |
|---|---|
| 冻结全部进程 → CPU 利用率接近 0 | 最不稳定的负载区间 |
| `PROCTHROTTLEMAX` 限频 → 最低 P-State | 最低电压 |
| 关闭射频 / 暂停维护 → 再减少负载 | 进一步逼近空载 |
| **持续整个合盖时长** | 数十分钟到数小时的持续低压空载 |

也就是说，在那些机器上使用本工具，等于**长时间把芯片按在它已知的失效工况里**。崩溃往往发生在合盖、黑屏、所有进程被冻结的状态下——蓝屏看不见、缓冲区没落盘、只能硬断电，**有数据损坏风险**。

**因此程序会在三处强制你确认风险**：

- **安装器**：勾选警告并点击「安装」后，若检测到该 CPU，会**再弹一次确认框**，写明本机 CPU 型号，选择「是」才继续安装
- **`start.cmd`**：检测到该 CPU → **在修改任何设置之前**弹出同样的警告确认框；选择「否」直接退出，**不碰合盖动作**
- **`Sleepify.exe`**：状态栏常驻红色「⚠ 高风险平台（Ryzen 标压）」，启动通知也会提示，但**不会阻止你使用**

匹配规则：`Ryzen [3-9] [5-7]xxx(H|HS|HX)`，例如 5800H / 5900HX / 6600H / 6800HS / 7840HS / 7945HX / 7535H。
U 系列（5800U / 7730U 等）与桌面型号（5600X / 5800X3D）不受影响。

### 其它机器

- ✅ 适用于：合盖睡眠 / 休眠会卡死、无法唤醒、离电无法休眠的机器
- ⚠️ 睡眠本来就正常的机器请谨慎使用——它会改变合盖行为，且**不能真正替代**系统睡眠的省电效果

## 原理

不是真正的睡眠。合盖时执行（可并行的全部并行）：

| 动作 | 实现 |
|---|---|
| 立即静音 | CoreAudio `IAudioEndpointVolume`（亚毫秒，在防抖延迟之前就执行） |
| 亮度降到 0 | WMI `WmiMonitorBrightnessMethods`——**面板保持供电**，绕开会死锁的 DPMS 掉电路径 |
| 射频开关 | Windows **Radio API**（与系统飞行模式/无线开关同一套接口），可保留 WLAN |
| 冻结进程 | `NtSuspendProcess` 冻结当前会话内所有可冻结进程，白名单除外 |
| 抑制维护 | 禁用自动维护窗口 + 暂停 `SysMain` / `WSearch` / `DoSvc` / `DiagTrack`（更新服务仅在 `TiWorker` 未运行时暂停） |
| 限制功耗 | `PROCTHROTTLEMAX` 可调的 CPU 上限 |

开盖时全部**并行还原**，实测整轮 1.6–1.8 秒（早期串行版本约 20 秒）。

## 安装

### 方式一：安装器（推荐）

1. 运行 `SleepifySetup.exe`（自提权）
2. 选择语言（中/英/法/俄/西/阿）、安装目录（默认 `C:\Sleepify`）、是否安装后自动运行设备检查
3. 阅读警告并勾选确认 → 安装

### 方式二：手动

把 `Sleepify.exe`、`start.cmd`、`start.ps1`、`uninstall.cmd`、`uninstall.ps1` 放进同一个文件夹，
右键 `start.cmd` → **以管理员身份运行**。

`start.cmd` 会：校验平台 → 探测硬件 → 写 `config\device.ini` → 生成睡眠计划写入 `config\config.ini`
→ 把插电/离电的合盖动作设为「不采取任何操作」→ 启用服务并启动主程序。

## 使用

- **托盘图标**：红点 = 已启用，绿点 = 已停用，点击切换
- **白名单**：点「白名单...」，从左侧拖动**图标**到右侧即可；白名单中的进程不会被冻结
- **`--silent` 参数**：由开机自启任务使用，只弹通知、不显示窗口。手动双击（无参数）才显示界面
- 已运行时再次双击 exe，会让正在运行的实例把窗口弹出来

### 运行时目录

```
<安装目录>\
    config\   config.ini  device.ini  whitelist.txt  enabled.flag  (sleepify.state 临时)
    logs\     sleepify.log  setup-log.txt  sleep-plan.txt  uninstall-log.txt
```

`device.ini` 是**逐机探测**的设备名（型号 / CPU / WLAN 适配器 / 蓝牙射频 / 亮度实例 / 是否有盖子），
由 `start.cmd` 写入一次，主程序读取后复用——不同机型的设备名不同，这一步不能省。

## 卸载

双击 `uninstall.cmd` → 确认 → 自动执行 8 步还原：

1. 结束进程
2. 删除计划任务 `Sleepify`
3. 合盖动作还原为「睡眠」
4. CPU 上限还原 100%、散热方式还原「主动」
5. 删除 `MaintenanceDisabled`（恢复自动维护）
6. 重启被暂停的后台服务
7. 射频全部打开
8. 删除 `%ProgramData%\Sleepify`

完成后弹框选择：**一键删除**（连目录带脚本一起删）或 **关闭**（保留目录，可再次 `start.cmd` 重新部署）。

## 已知限制

- **平台拦截**：Ryzen 5000/6000/7000 移动端 H/HS/HX 被硬性拒绝（见文首）
- **Microsoft Defender 无法冻结**：`MsMpEng` 等是 PPL（受保护进程），用户态连句柄都拿不到。本工具退而抑制**触发它工作的维护窗口**
- **蓝牙**：只有在 Radio API 里注册了 Bluetooth 射频的机器才能关闭；否则**完全不碰**（强停 `bthserv` 会把射频搞成 Error 状态）
- **亮度控制**依赖 WMI，部分台式机/外接屏不可用——不可用时自动跳过，不会留下黑屏
- **冻结范围**仅限当前用户会话，系统服务（session 0）不受影响
- 冻结期间**不要拔插移动硬盘**、不要在写入密集操作中合盖
- 需要 **.NET Framework 4.8**（Win10 1903+ / Win11 自带）
